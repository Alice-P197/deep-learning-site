大模型与微调：从预训练到对齐

大语言模型不是一个新算法，而是“Transformer + 海量数据 + 规模化训练”的产物。 真正让它可用的是三阶段流水线：预训练获得能力，监督微调学会听指令，偏好对齐学会说人话。

12.1 规模化：Scaling Law 与能力涌现

经验规律是：模型损失随参数量、数据量、计算量按幂律下降。在某个规模之后， 一些能力（多步推理、代码、指令跟随）会突然出现，称为涌现。

Chinchilla 式数据—参数配比
Nopt ≈ C / 20,    Dopt ≈ 20N

在固定计算预算下，参数量与训练 token 数应大致按 1:20 配比。 早期模型普遍“参数过大、数据不足”，后来 LLaMA 等把训练 token 提升到数万亿。

幂律损失曲线
L(N,D) = L∞ + a/Nα + b/Dβ

L∞ 是不可约损失。α、β 约为 0.3 量级， 意味着规模翻倍只能带来有限下降——这正是“数据质量比堆量更重要”的原因。

Tokenization：模型的“字母表”

BPE / WordPiece / Unigram 把文本切成子词。词表太小导致序列变长，太大导致嵌入矩阵膨胀。 中文与代码的切分质量会直接影响训练效率与推理成本。

上下文长度

训练时的上下文长度决定了位置编码与注意力模式。推理时外推到更长序列， 需要 RoPE 插值、NTK 缩放或继续训练，否则效果会显著下降。

12.2 三阶段流水线

  1. 预训练（Pretraining）：在数万亿 token 上做下一个词预测， 获得语言、知识与推理的基础能力。成本最高，通常只有大机构做。
  2. 监督微调（SFT）：用高质量的“指令—回答”对，让模型学会遵循格式与任务指令。 数据量从百万到几万不等，质量远比数量重要。
  3. 偏好对齐（RLHF / DPO）：用人类偏好数据让模型更有帮助、更安全、更符合风格。 这是“会答题”到“答得好”的关键一步。
阶段数据目标典型规模
预训练网页、书籍、代码CLM1T+ tokens
SFT指令—回答对CLM（只对回答算损失）1K~1M 条
RM偏好对（chosen / rejected）Bradley-Terry 回归10K~1M 对
RLHF提示词 + 奖励模型PPO 最大化奖励在线采样
DPO偏好对直接优化策略10K~100K 对
SFT 的损失掩码

计算损失时只对“回答”部分计算，指令部分 label 设为 -100。 如果对整段计算，模型会花大量容量去拟合用户提问，指令跟随能力反而下降。

12.3 参数高效微调：LoRA 与 QLoRA

全参微调一个 70B 模型需要数百 GB 显存。LoRA 假设权重更新是低秩的， 只训练两个小矩阵 A、B，冻结原权重。

LoRA 的低秩分解
W′ = W + ΔW = W + αr BA,    A ∈ Rr×din, B ∈ Rdout×r

r 通常取 4~64，远小于 d。可训练参数从 dout×din 降到 r×(din+dout)。A 随机初始化、B 初始化为零，保证训练开始时 更新为零，不破坏原模型。

QLoRA：4-bit 量化 + LoRA
Wq = quantize(W, 4bit),    y = xWq + xΔW

主干权重以 NF4 4-bit 存储，反量化后参与计算；LoRA 分支保持 16-bit。 这让 7B 模型可以在单张 24GB 显卡上微调。代价是训练速度略慢。

方法可训练参数显存适用
Full fine-tune100%极高数据充足、追求极限效果
LoRA0.1%~1%低多任务切换、快速迭代
QLoRA0.1%~1%很低单卡微调大模型
Adapter1%~5%低需要插入式模块
Prefix / Prompt<0.1%极低少样本、冻结主干

12.4 对齐：RLHF 与 DPO

奖励模型学习人类偏好：给定同一提示的两个回答，预测哪个更好。RLHF 用 PPO 最大化奖励， 同时用 KL 惩罚防止模型偏离原始分布太远。

RLHF 目标
maxπ Ex~D, y~π[ rφ(x,y) − βDKL(π‖πref)]

奖励让回答更好，KL 让模型别为了刷分而输出怪话。 β 控制两者的平衡，是 RLHF 最关键的旋钮之一。

DPO：把偏好直接写成分类损失
LDPO = −log σ( β[log πθ(yw|x) − log πref(yw|x)] − β[log πθ(yl|x) − log πref(yl|x)])

yw 是偏好回答，yl 是被拒绝回答。 DPO 不需要奖励模型与在线采样，训练更简单稳定，已成为开源模型对齐的主流。

对齐税

对齐会让模型更安全、更有帮助，但也可能牺牲多样性、创造力与某些基准分数。 评测时必须同时看能力、安全与风格三类指标，不能只盯一个榜单。

12.5 推理、RAG 与智能体

检索增强生成（RAG）

把外部知识切块、向量化、检索后拼进上下文。优点是知识可更新、可溯源； 难点是切块策略、召回质量与上下文长度。

工具调用 / 智能体

模型输出结构化动作（搜索、计算、代码执行），环境返回结果后再继续推理。 关键在工具描述、错误处理与循环终止条件。

场景推荐方案原因
知识频繁更新RAG无需重训，可溯源
固定领域风格SFT / LoRA把风格写进权重，推理零额外成本
需要多步计算工具调用把精确计算交给外部程序
偏好与安全DPO / RLHF直接优化人类偏好

12.6 代码：LoRA 层与 DPO 损失

Python · LoRA 线性层
import math
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=8, alpha=16, dropout=0.0):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False          # 冻结原权重

        self.r, self.scale = r, alpha / r
        self.A = nn.Parameter(torch.randn(r, base.in_features) / math.sqrt(base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))
        self.drop = nn.Dropout(dropout)

    def forward(self, x):
        out = self.base(x)
        lora = self.drop(x) @ self.A.t() @ self.B.t()
        return out + lora * self.scale

base = nn.Linear(512, 512)
layer = LoRALinear(base, r=8)
x = torch.randn(4, 512)
print(layer(x).shape)
print("trainable:", sum(p.numel() for p in layer.parameters() if p.requires_grad))
Python · DPO 损失
import torch
import torch.nn.functional as F

def dpo_loss(policy_w, policy_l, ref_w, ref_l, beta=0.1):
    """四个输入都是序列的 log 概率之和，形状 (B,)。"""
    margin = (policy_w - ref_w) - (policy_l - ref_l)
    return -F.logsigmoid(beta * margin).mean()

B = 4
policy_w, policy_l = torch.randn(B, requires_grad=True), torch.randn(B, requires_grad=True)
ref_w, ref_l = torch.randn(B), torch.randn(B)
loss = dpo_loss(policy_w, policy_l, ref_w, ref_l)
loss.backward()
print(loss.item())
log 概率要按 token 求和

DPO 比较的是整段回答的对数概率。实现时必须把每个 token 的 log-prob 求和， 并只统计回答部分，否则长度不同的回答会被系统性偏向。

12.7 本章小结

大模型落地的关键

  • 预训练决定能力上限，数据质量与配比决定效率。
  • SFT 决定会不会听指令，只对回答算损失。
  • LoRA / QLoRA 让单卡微调成为可能，r 与 alpha 是主要超参。
  • RLHF 用奖励模型 + KL 约束，DPO 用偏好对直接优化。
  • RAG 解决知识更新，工具调用解决精确计算。
  • 评测要防止数据污染，并同时看能力、安全与效率。

常见误区

  1. SFT 数据只追求数量，忽略多样性与正确性。
  2. LoRA 的 B 不初始化为零，训练一开始就破坏原模型输出。
  3. DPO 的 beta 设得过大，模型几乎不更新；过小则偏离参考模型太远。
  4. 用训练集同分布的题目做评测，得到虚高分数。
  5. 把上下文窗口当成“记忆力”，忽略中间位置的信息丢失问题。
