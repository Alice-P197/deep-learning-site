工程实践：把实验变成可复现的系统

研究代码与生产代码的区别不在模型，而在数据、配置、日志、测试与协作。 本章给出构建可靠训练系统的清单：先保证可复现，再谈性能。

预计 50 分钟前置：第 4 章 关键词：数据管线 · 可复现 · 调试 · DDP

14.1 数据管线

模型上限由数据决定。一个可靠的数据管线要回答四个问题：数据从哪来、 如何清洗、如何切分、如何版本化。任何一环缺失，实验结论都不可信。

环节关键动作常见事故
采集记录来源、时间、许可混入评测集、版权不清
清洗去重、去噪、脱敏、语言识别去重不彻底导致指标虚高
标注指南、双人标注、一致性检验标注标准漂移
切分按用户/时间分组切分同源样本跨集泄漏
版本内容哈希 + 处理脚本版本数据被就地覆盖无法回溯
切分比洗数据更容易出错

同一用户的多条记录、同一文档的多个片段、同一事件的重复报道， 都属于“同源”。随机切分会让训练集与测试集共享这些信息，指标会明显偏高。 正确做法是按实体或时间做分组切分。

14.2 可复现的五个要素

  1. 代码版本提交哈希写进日志；未提交的改动要显式标记为 dirty。
  2. 数据版本用内容哈希或清单文件锁定，而不是“最新目录”。
  3. 环境版本Python、CUDA、PyTorch、驱动与依赖锁文件一并记录。
  4. 随机性种子、确定性算子、数据加载顺序都要控制。
  5. 配置所有超参进配置文件并随实验存档，禁止散落在命令行。
python · 种子与确定性 
import os
import random

import numpy as np
import torch


def set_seed(seed: int = 42) -> None:
    """固定所有随机源，尽量保证实验可复现。"""
    os.environ["PYTHONHASHSEED"] = str(seed)
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)

    # 确定性算法会牺牲一些速度，调试阶段建议开启
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
    torch.use_deterministic_algorithms(True, warn_only=True)

    # DataLoader 的 worker 也需要独立的种子来源
    def seed_worker(worker_id: int) -> None:
        worker_seed = seed + worker_id
        np.random.seed(worker_seed)
        random.seed(worker_seed)

    return seed_worker

14.3 调试：从最小可复现开始

训练不收敛时，不要随机改超参。按下面的顺序做二分排查， 每一步都应该是可证伪的小实验。

现象优先检查快速验证
损失是 NaN学习率、除零、log(0)、混合精度溢出调小 lr，关闭 AMP，加 clip
损失不下降标签错位、学习率过小、梯度被切断单 batch 过拟合测试
训练升验证降过拟合、数据泄漏、切分错误检查同源样本与正则
指标突然跳水数据分布变化、学习率调度、脏样本回放最近一个 checkpoint
多卡结果异常BN 统计、梯度同步、采样重复换单卡对比同种子

单批过拟合测试

取一个固定 batch，关闭正则与数据增强，训练几十步。若损失无法降到接近 0， 说明模型或代码有结构性错误，而不是数据问题。这是最省时间的排查手段。

python · 单批过拟合 
import torch
from torch import nn


def overfit_one_batch(model, batch, steps=200, lr=1e-3):
    """用一个 batch 反复训练，验证模型与损失实现是否正确。"""
    model.train()
    x, y = batch
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    loss_fn = nn.CrossEntropyLoss()

    for step in range(steps):
        logits = model(x)
        loss = loss_fn(logits, y)

        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()

        if step % 20 == 0:
            acc = (logits.argmax(dim=-1) == y).float().mean().item()
            print(f"step {step:3d}  loss {loss.item():.4f}  acc {acc:.3f}")

    assert loss.item() < 0.1, "单批都无法过拟合，先查模型或标签"
    return model

14.4 评测体系

离线指标、线上指标与人工评估各有盲区。成熟的做法是三层评测： 单元级（单条样本回归）、集合级（固定测试集）、线上级（A/B 与真实流量）。

01

单元回归

为每个已知 bug 保留一条测试样本，防止修复被回滚。

02

固定测试集

版本化、去重、防泄漏；报告置信区间而非单点数字。

03

线上评估

A/B、影子流量、人工抽检，关注业务指标而非仅损失。

警惕评测污染

公开基准可能已进入预训练语料。报告结果时应说明是否做过污染检测， 并补充私有测试集与扰动测试（改写、换序、加噪）。

14.5 分布式训练入门

单卡放不下时有三条路：数据并行、张量并行、流水并行。 最常见的是分布式数据并行（DDP），每张卡持有完整模型，处理不同数据， 反向传播时对梯度做 all-reduce 求平均。

DDP 的有效批大小
Beff = Bper · Ngpu · Aaccum

换卡数或改梯度累积时，要同步调整学习率与 warmup， 否则等价于换了一套训练配置，曲线不可直接比较。

bash · DDP 启动 
# 单机 4 卡
torchrun --nproc_per_node=4 train_ddp.py \
    --batch-size 32 --grad-accum 2 --lr 3e-4

# 多机：每台机器都要设置相同的 master 地址与端口
# node 0
torchrun --nnodes=2 --node_rank=0 --master_addr=10.0.0.1 \
    --master_port=29500 --nproc_per_node=8 train_ddp.py

# node 1
torchrun --nnodes=2 --node_rank=1 --master_addr=10.0.0.1 \
    --master_port=29500 --nproc_per_node=8 train_ddp.py
python · DDP 最小骨架 
import os

import torch
import torch.distributed as dist
from torch import nn
from torch.nn.parallel import DistributedDataParallel as DDP


def main() -> None:
    dist.init_process_group("nccl")
    rank = dist.get_rank()
    torch.cuda.set_device(rank)

    model = nn.Linear(128, 10).cuda(rank)
    model = DDP(model, device_ids=[rank])

    opt = torch.optim.AdamW(model.parameters(), lr=3e-4)
    for step in range(10):
        x = torch.randn(32, 128, device=rank)
        loss = model(x).sum()
        opt.zero_grad(set_to_none=True)
        loss.backward()          # 梯度在这里自动 all-reduce
        opt.step()
        if rank == 0:
            print(step, loss.item())

    dist.destroy_process_group()

并行策略怎么选

策略切分对象通信量适用
DDP数据梯度 all-reduce模型能放进单卡
ZeRO / FSDP参数、梯度、优化器状态较高，可重叠单卡放不下但层可切
张量并行 TP单层内矩阵每层两次 all-reduce单机多卡、低延迟推理
流水并行 PP按层分段段间激活传递跨机、超深模型

14.6 实验管理与协作

配置即代码

用 YAML 或 dataclass 管理超参，实验输出目录带时间戳与配置快照， 禁止手工改默认值后忘记记录。

日志三件套

指标曲线、样本级预测、系统指标（显存、吞吐、数据加载耗时）。 只记录损失不足以定位问题。

Checkpoint 策略

按步数与时间双触发保存，保留最近 N 个与最佳指标版本， 并验证能从 checkpoint 完整恢复优化器与调度器状态。

本章要点

  • 数据切分要按实体或时间分组，随机切分极易造成泄漏。
  • 可复现依赖代码、数据、环境、随机性、配置五要素同时锁定。
  • 调试从单批过拟合开始，先证明模型能学会，再怀疑数据与超参。
  • DDP 改卡数或累积步数时，必须同步调整学习率与 warmup。
  • 评测要防污染，报告置信区间而不是单点分数。

常见误区

  1. 用测试集调超参，最终指标无法代表泛化能力。
  2. 只保存模型权重，不保存优化器与调度器状态，无法续训。
  3. 在多卡上使用普通 BatchNorm，统计量不同步导致结果异常。
  4. 数据加载成为瓶颈却一直优化模型，GPU 利用率长期低于 50%。
  5. 实验目录随手命名，几周后无法复现任何一条曲线。
