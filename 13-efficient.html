13.1 部署到底在优化什么

同一模型在不同场景下的目标函数完全不同。离线批处理追求吞吐（tokens/s）， 在线对话追求首 token 延迟（TTFT）与单 token 延迟（TPOT），端侧追求内存占用与功耗。 先明确目标，再选技术，否则容易做了大量压缩却没有任何收益。

指标含义典型瓶颈优先手段
显存占用权重 + 激活 + KV Cache权重精度、批大小量化、PagedAttention
TTFT请求到第一个 token预填充计算FlashAttention、前缀缓存
TPOT相邻 token 间隔访存带宽量化权重、KV Cache 压缩
吞吐单位时间总 token批处理效率连续批处理、更大 batch
成本每百万 token 花费GPU 利用率规格匹配、弹性调度
先测量再优化

没有 profile 的压缩都是猜测。用 nvidia-smi、Nsight Systems、 PyTorch Profiler 先确认是计算受限（compute-bound）还是访存受限（memory-bound）。 大模型解码阶段几乎总是访存受限，因此降低权重位宽收益最大。

13.2 量化：用更低位宽表示权重

量化把浮点张量映射到整数网格。核心是两个参数：缩放因子 s 与零点 z。

仿射量化与反量化
q = round(x / s) + z,    x̂ = s(q − z)

对称量化取 z = 0，适合权重；非对称量化适合激活，因为激活分布常偏移。 s 由校准数据的最大绝对值决定：s = max|x| / (2b-1 − 1)。

量化误差与离群值
Δx ≤ s/2,    s ∝ max|x|

一个极端离群值会把 s 撑大，导致其余数值精度骤降。 这就是 LLM 量化需要 AWQ（按通道保护显著权重）或 SmoothQuant（把激活难度迁移到权重）的原因。

PTQ 与 QAT

训练后量化 PTQ

直接对已训练模型量化，用少量校准数据统计激活范围。速度快、成本低， 8 bit 通常无损，4 bit 需要更精细的算法（GPTQ、AWQ、GGUF 系列）。

量化感知训练 QAT

训练时插入伪量化节点，让模型学会适应舍入误差。精度更好， 但需要训练资源与标注数据，通常用于端侧小模型。

方案位宽特点适用
动态 INT88激活运行时量化，无需校准CPU、BERT 类模型
静态 INT88需校准集，延迟最低CNN 服务端
GPTQ4 / 3逐层二阶误差补偿GPU 上的 LLM
AWQ4保护 1% 显著通道，精度更稳LLM 通用
GGUF Q4_K_M4~5混合精度块量化，CPU 友好llama.cpp 本地推理
FP88硬件原生支持，几乎无损H100 及以后

13.3 剪枝与稀疏

剪枝移除不重要的连接或通道。非结构化剪枝（单个权重置零）需要稀疏硬件才能真正加速； 结构化剪枝（整通道、整头）可以直接改变矩阵形状，是实际部署的主流。

结构化剪枝的通道重要性
Ic = λ‖Wc‖2 + Σi |γc,i|

常见做法是给 BN 的 γ 加 L1 正则，训练后按 γ 大小剪掉通道， 再短程微调恢复精度。注意力头剪枝则依据输出投影的范数。

稀疏不等于加速

2:4 结构化稀疏在 Ampere 之后有 Tensor Core 支持可提速； 随机 90% 稀疏在普通 GPU 上往往和稠密一样慢。剪枝前先确认硬件与算子库支持。

13.4 知识蒸馏

用大模型（教师）的输出分布指导小模型（学生）。软标签携带的类别相似性信息 比独热标签更丰富，因此学生常常超过同规模直接训练的效果。

带温度的 KL 蒸馏损失
L = (1−α)·LCE(y, ps) + α·T2· KL(ptT ‖ psT)

pT = softmax(z / T)。T 越大分布越平缓、暗知识越多； 乘 T2 是为了让梯度量与温度无关。α 通常取 0.5~0.9。

大模型场景还有“序列级蒸馏”：学生在教师采样的回复上做 SFT， 或用教师的 logits 做 token 级 KL。后者信息量更大，但需要教师在线前向，成本更高。

PagedAttention 与连续批处理

传统实现为每个请求预分配最大长度的 KV Cache，碎片浪费可达 60% 以上。 PagedAttention 把 KV Cache 切成固定大小的块，用块表按需映射，显存利用率接近 100%； 连续批处理则在序列结束时立刻换入新请求，避免整批等待最慢的那条。

KV Cache 显存估算
MKV = 2 · L · Hkv · dhead · S · B · b

2 表示 K 与 V，L 为层数，Hkv 为 KV 头数（GQA 可远小于 Q 头数）， S 为序列长度，B 为批大小，b 为字节数（FP16 为 2）。这是长上下文服务的第一成本项。

13.6 一次完整的显存估算

以 7B 模型、FP16、批大小 8、序列 2048 为例：权重约 14 GB； 若 32 层、32 个 KV 头（MHA）、头维 128，则每 token 的 KV 约 0.5 MB， 单请求 2048 token 约 1 GB，8 条并发就是 8 GB。加上激活与框架开销， 一张 24 GB 卡很快见底——这就是要用量化与 GQA 的原因。

python · 显存与吞吐估算 
def kv_cache_gb(layers, kv_heads, head_dim, seq_len, batch, bytes_per=2):
    """返回 KV Cache 显存占用（GB）。"""
    per_token = 2 * layers * kv_heads * head_dim * bytes_per
    total = per_token * seq_len * batch
    return total / 1024 ** 3


def weight_gb(params_billion, bits=16):
    """按位宽估算权重显存（GB）。"""
    return params_billion * 1e9 * bits / 8 / 1024 ** 3


if __name__ == "__main__":
    print("7B FP16 权重:", round(weight_gb(7, 16), 2), "GB")
    print("7B INT4 权重:", round(weight_gb(7, 4), 2), "GB")
    for batch in (1, 8, 32):
        kv = kv_cache_gb(32, 32, 128, 2048, batch)
        print(f"batch={batch:3d}  KV Cache: {kv:.2f} GB")
部署前的三个问题

1）目标硬件是什么，支持哪些精度与算子？2）SLA 要求多低的 TTFT/TPOT？ 3）精度允许下降多少（用任务指标而非困惑度衡量）？回答完这三个问题，技术选型基本确定。

13.7 服务化要点

  1. 规格匹配先把模型压到能装进一张卡，再考虑多卡并行。 张量并行适合单机多卡，流水并行适合跨机，但通信开销会吃掉收益。
  2. 批处理策略在线服务用连续批处理与小批量降低延迟； 离线任务用大 batch 提升吞吐，二者不要混用同一配置。
  3. 缓存复用系统提示词、长文档前缀可做前缀缓存（prefix cache）， 多轮对话可复用历史 KV，显著降低重复计算。
  4. 监控与降级记录队列长度、P99 延迟、显存碎片； 过载时降级到更小模型或缩短最大输出，而不是直接超时。
  5. 版本与回滚权重、tokenizer、推理引擎版本必须一起锁定， 否则会出现输出漂移这类难以复现的问题。

本章要点

  • 解码阶段访存受限，降低权重位宽通常是最有效的加速手段。
  • 量化关键是处理离群值：AWQ 保护显著通道，SmoothQuant 迁移激活难度。
  • 结构化剪枝才容易真正加速，稀疏加速依赖硬件与算子支持。
  • 蒸馏用软标签传递暗知识，温度 T 与权重 α 是两个核心超参。
  • LLM 服务的第一成本项是 KV Cache，PagedAttention 解决碎片浪费。

常见误区

  1. 只看困惑度评估量化，忽略下游任务指标与长尾输入。
  2. 对所有权重统一量化，未保护嵌入层与输出层。
  3. 以为参数量小就一定快，忽略算子融合与内存布局。
  4. 用训练吞吐推断线上延迟，两者瓶颈完全不同。
  5. 忽略 tokenizer 与推理引擎版本，导致结果不可复现。
